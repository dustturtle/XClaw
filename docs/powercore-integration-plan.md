# XClaw 空终答修复与 PowerCore 接入计划

记录日期：2026-09-05

以下保留最初确认的实施顺序，遵循奥卡姆剃刀原则，优先泛化方案。实施说明见 [PowerCore 接入](powercore-integration.md)。

1. **先修复 XClaw 的空终答问题。** 这是当前已经复现的问题。从 XClaw 的实际对话入口定位原因，做最小必要修复，并验证多轮对话和工具调用后的最终回复。
2. **把 PowerCore 独立成仓库时建立 API 和镜像版本契约。** 明确 API 请求、响应及 SSE 事件的兼容范围，以及镜像版本与 API 版本的对应关系，供 XClaw 接入和升级时使用。
3. **第一阶段先接只读工具。** 先验证 XClaw 与 PowerCore 的最小调用闭环，首阶段接入范围限定为只读工具。
4. **接记忆、持仓、自选股、定时任务时，再完成可信主体映射。** 由服务端确定工具操作所属的用户和会话，确保这些有状态能力按主体隔离。

后续任务已明确授权修改 XClaw 和同级独立 PowerCore；不使用 poweragent 内的历史副本。实施及验收结果另记本地报告，不把计划项当作已经验证的结论。
